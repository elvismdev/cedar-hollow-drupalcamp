## Image spikes

Run on 2026-10-29 in DDEV on a database snapshot that was restored afterwards (Focal Point and Crop API were installed for the spikes and removed), plus one check on Pantheon Dev using temporary files that were deleted. The test photo was a 4.9 MB CC0 file from Wikimedia Commons ("Forest of Himalayan Cedar Tress in Shimla").

| Spike | Check | Result | Evidence |
| --- | --- | --- | --- |
| I1 | Creating an Image media type changes Canvas's stored components or pages. | Pages unchanged | The featured card and quote gained a new component version whose `image` prop is an entity reference to Image media with the `media_library_widget`; a dump of `canvas_page__components` before and after was identical. |
| I2 | Focal Point crops survive the content export. | Pass, with a separate crop export | A 16:9 Focal point scale and crop plus Convert to AVIF turned the photo into a 1600x900 AVIF of 194 KB in 1.1 s, cropped at the focal point (the canopy, not the centre). `content:export media --with-dependencies` exported the file and binary but not the crop; `content:export crop` exported it with its file as a UUID; after deleting the crop, a recipe import restored it linked to the same file with the same coordinates (1560, 624). |
| I3 | `content:export node --with-dependencies` exports media embedded in a text field. | Fail | A session body holding a `<drupal-media>` embed exported with its track and speaker but not the media. Embedded media must be exported as their own set. |
| I4 | A theme-layer hero renders eager with high fetch priority and correct dimensions. | Pass | A responsive image style mapping 800 and 1600 wide 16:9 styles, the formatter set to eager and `#attributes['fetchpriority'] = 'high'` rendered `<img loading="eager" fetchpriority="high" srcset="...800w, ...1600w" sizes="100vw" width="800" height="450">`, all AVIF. A block placed in `highlighted` with front-page visibility rendered on the Canvas home page and not on `/about`. |
| I5 | The home page's baseline performance and layout shift. | CLS from the menu | Lighthouse 12.8.2 mobile on DDEV: performance 99, LCP 0.8 s, CLS 0.069. A `layout-shift` observer at 412 by 823 recorded one shift of 0.34 at about 100 ms, sourced from `.site-header__navigation` (100px to 44px) and `.page__main`: the main menu collapsing when its script runs. |
| I6 | AVIF derivative cost on Pantheon Dev. | Measured | Scale and crop plus Convert to AVIF on the same photo: 800x450 in 776 ms (76 KB), 1600x900 in 1623 ms (195 KB). |
| I7 | The Media Library check: the permissions `demo_editor` needs for Canvas's media picker, and whether the add form enforces the licence fields. | Pass | Canvas image props open core's field-widget Media Library opener: `MediaLibraryUiBuilder::checkAccess()` requires `view media` (granted to authenticated users by the media recipe), `MediaLibraryFieldWidgetOpener::checkAccess()` requires update access to the edited entity (the editor already has it for Canvas pages), and `buildMediaTypeAddForm()` requires create access for the media type, so `demo_editor` gains `create image media` only; `access media overview` (the `/admin/content/media` listing) is not needed and is not granted. The licence fields are required on the field definitions and placed on the `media_library` form mode, so the add form refuses an upload without them; `MediaLicenceTest` asserts it. |

## Findings that change the plan

* **A code component can be created without the Canvas editor.** Canvas expects the compiled code as an ES module that imports `react/jsx-runtime` and `react`, which its import map points at Preact. `esbuild <file>.jsx --format=esm --jsx=automatic --jsx-import-source=react` produces that format, and a `JavaScriptComponent::create()` call with `js.original` and `js.compiled` validated with no violations and rendered. The agenda builder can therefore be built from its repository file by a script, instead of being pasted into the editor by hand.
* **Content export command.** In Drupal 11.4, `core/scripts/drupal` is deprecated in favour of `dr`, and running it from `web/` fails in this Composer layout because it looks for `vendor/` inside `web/`. Drush 13.8 provides the same command: `ddev drush content:export <entity_type> <id> --with-dependencies --dir=/var/www/html/recipes/<recipe>/content`.
* **Exported Canvas pages drop `component_version`**, and the recipe fills it in on import.
